Bước 1 — Upload tài liệu web/uploadTransport.ts · routes/documents.rs

Người dùng kéo thả file vào trang Thư viện. Web gửi multipart POST /api/v1/documents kèm Bearer token. Upload phiên bản mới của tài liệu cũ = gửi kèm documentId — server nối vào lineage phiên bản thay vì tạo tài liệu mới.

Kiểm tra an ninh
Đối chiếu magic bytes với định dạng khai báo (vì vậy file .txt trần bị từ chối — phải là docx/pdf/xlsx…). RBAC + RLS theo tổ chức.
Ghi bền vững
Lưu file gốc vào storage, tạo bản ghi document + version, rồi enqueue job trong cùng transaction — không bao giờ có file mà mất job.
Theo dõi tiến độ
Web mở SSE /jobs/{id}/events xem trạng thái job chuyển đổi theo thời gian thực.
job Convert được worker nhận (lease)
Bước 2 — Convert: file gốc → Markdown workers/convert.rs · fileconv-core · services/ocr_normalize.rs

Worker gọi bộ chuyển đổi fileconv (code dự án tự chủ) qua subprocess cách ly: Linux dùng sandbox Landlock, Windows/dev chạy trực tiếp. Định tuyến theo đuôi file:

·
DOCX / XLSX
docx-rust / calamine
Run-level text, heading theo style; mọi sheet, merge → HTML table
·
Audio
Whisper
PhoWhisper ưu tiên tiếng Việt, cache model LRU
Chuẩn hoá sau chuyển đổi (ocr_normalize.rs, chạy TRƯỚC khi lưu artifact): map unicode hyphen/khoảng trắng lạ về ASCII, sửa ký tự OCR sai, nối dòng gãy, nâng heading văn bản pháp lý (Điều/Chương/Mục). Toàn bộ output chuẩn hoá NFC — quan trọng với tài liệu tiếng Việt.
markdown artifact đã lưu → job Index
Bước 3 — Index: chia chunk + tìm kiếm từ khóa workers/index.rs
Chia chunk theo heading
Markdown được cắt thành các chunk RAG theo cấu trúc heading, giữ đường dẫn tiêu đề cha (vd: "Chương II › Điều 5") để trích dẫn có ngữ cảnh.
Postgres FTS
Mỗi chunk ghi vào Postgres kèm chỉ mục full-text. Từ đây tìm được bằng từ khóa
Nối tiếp
Index xong enqueue một job EmbeddingBatch — chunk là bất biến, embedding làm sau không chặn tìm kiếm từ khóa.
job EmbeddingBatch
Bước 4 — Embedding: tìm kiếm theo nghĩa workers/embedding.rs · storage/qdrant.rs

Worker gom chunk theo batch có giới hạn, gọi embedding provider đã duyệt, rồi upsert vector vào Qdrant (point id sinh từ org + collection + chunk — chạy lại không tạo trùng). Từ đây tìm kiếm theo nghĩa hoạt động

Provider lỗi/chậm chỉ làm chậm nhánh vector — tài liệu vẫn hỏi đáp được bằng từ khóa trong lúc chờ.

tài liệu sẵn sàng — người dùng đặt câu hỏi

Chế độ phiên bản: câu hỏi có thể chạy ở chế độ hiện hành (current), tại thời điểm (as-of), so sánh 2 phiên bản (compare) hoặc lịch sử thay đổi (history) — bộ kiểm chứng biết phân biệt trích dẫn phiên bản cũ/mới, bắt lỗi gán giá trị bản mới cho bản cũ.
Kiểm chứng từng câu (mức từ vựng, chạy local): citation phải tồn tại và đúng nguồn; số liệu / ngày tháng / đơn vị / mã hiệu văn bản trong câu phải khớp đoạn nguồn; phát hiện phủ định ngược. Câu vi phạm bị loại; phần còn lại phải qua lại toàn bộ kiểm tra. Bộ kiểm chứng suy diễn (structured entailment) chưa có → mọi câu trả lời LLM đều dán nhãn "chưa xác minh đầy đủ" (dev-gate), hoặc hệ thống rơi về trích xuất thuần.

Hạ tầng & các chế độ trả lời
  • Postgres — tài liệu, chunk, FTS, sự kiện SSE bền vững, RLS đa tổ chức
  • Qdrant — vector embedding cho tìm kiếm theo nghĩa
  • Storage — file gốc + markdown artifact
  • OpenRouter — 3 vai trò tách biệt: OCR vision (convert), embedding (index/hỏi), chat (trả lời)
  • Worker nền — Convert, Index, EmbeddingBatch, Reconcile, Delete (lease + heartbeat)
  • trích xuất đoạn nguồn nguyên văn — mặc định an toàn
  • llm chưa xác minh qua kiểm tra trích dẫn, dev-gate bật
  • fallback LLM lỗi/không đạt kiểm chứng → về trích xuất

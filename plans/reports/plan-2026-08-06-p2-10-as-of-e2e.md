## Objective

Close the remaining P2-10 `as_of` UI/evidence gap while preserving the backend's
existing scope-wide semantics: at a requested timestamp, retrieval considers the
effective published version of every document in the authorized collection/project
scope. The web client must require and send the timestamp without inventing a
document selector that the server does not use.

## Context

The owner selected scope option 1 on 2026-08-06: keep current backend behavior and add
time-based end-to-end coverage. `services::retrieval` maps `VersionMode::AsOf` to
`db::search::resolve_as_of_version_ids`, which resolves one version per in-scope
document and deliberately sets no `document_filter`. `ChatPanel` already rendered a
`datetime-local` control and sent `asOf`, but the control was not required and the
submit button did not guard an empty value.

The web mock previously did not match that contract: its `as_of` branch required
`documentId` and resolved only that document. Stale Playwright/catalog comments called
the absent `as_of` document picker a UI gap. This task corrected the mock and evidence
to the authoritative backend semantics; it did not add that picker or alter the public
API.

## Implementation plan

1. Add a failing focused component/integration test proving `as_of` cannot submit
   without a timestamp and that a valid submission sends an ISO `asOf` value without
   `documentId`.
2. Add a failing Playwright scenario that selects a timestamp between the two seeded
   versions of the budget document, asks the budget question, and observes the
   effective v1 answer/citation plus its non-current warning.
3. Refactor the mock `as_of` resolver to select the latest effective version of every
   document in the already-authorized collection/project scope, then apply the normal
   query/limit behavior. Invalid/missing timestamps fail closed with no passages and a
   deterministic warning.
4. Make the timestamp input required at the UI boundary and keep the submit action
   disabled until both question and timestamp requirements are satisfied.
5. Remove stale comments/catalog claims that describe a missing document picker as the
   blocker, record test evidence, and move P2-10 to `Review`.
6. Obtain independent code/security review. Move P2-10 and this plan to `Done` only
   after all Critical/Important findings are resolved and required checks pass.

## Security and migration notes

No API, database migration, dependency, auth, RBAC, ACL, storage, or logging change is
planned. The mock must derive its maximum collection scope from the active token's org
profile `allowedCollectionIds`; project/request filters may only narrow it, and
unauthorized/mixed/empty scope must fail closed. The component request test must not log
prompts or document content.

This is adjacent to tenant-scoped retrieval behavior, so independent review must verify
that the mock cannot broaden collection scope and that omission of `documentId` matches
the server rather than weakening authorization. No migration or rollback procedure is
applicable; rollback is a scoped revert of web tests/mock/UI validation.
